# Инструкции для Codex

Эти правила действуют для всех задач по разработке в репозитории
`homoprovincialis/Homo-Provincialis` и для всех его каталогов.

## Безопасная работа с GitHub

Ветка `main` — основная рабочая версия сайта, публикуемая через GitHub Pages.
Codex не должен самостоятельно вносить изменения непосредственно в `main`
или выполнять слияние Pull Request.

### Порядок выполнения каждой задачи

1. Получить актуальное состояние `main` из `origin` и создать от него отдельную
   ветку для задачи. Сохранить существующие пользовательские изменения.
2. Выполнять изменения и коммиты только в этой отдельной ветке.
3. Проверить результат, отсутствие ошибок и состав изменений перед публикацией.
   Запустить проверки, соответствующие задаче, и сообщить об их результатах.
4. Отправить ветку в GitHub и создать Pull Request с целевой веткой `main`.
5. Предоставить владельцу краткий отчёт об изменениях, проверках и ссылку на
   Pull Request.
6. Оставить Pull Request открытым до решения владельца. Создание Pull Request
   не является разрешением на его слияние.

### Запреты без отдельного явного разрешения владельца

- Выполнять Merge, Squash Merge или иное слияние Pull Request в `main`.
- Включать автоматическое слияние Pull Request.
- Выполнять прямые коммиты или push в `main`.
- Изменять или отключать правила защиты ветки `main`.
- Выполнять принудительный push (`--force`, `--force-with-lease` и аналоги).
- Удалять основную ветку `main`.

Если доступ к GitHub или другая внешняя зависимость мешает открыть Pull Request,
сохранить выполненную работу в отдельной ветке, сообщить о конкретном препятствии
и не обходить его прямым изменением `main`.
