# World Direct Democracy System: сохранность данных

Изменение относится только к локальному браузерному прототипу прямой демократии.
Рабочие данные посетителей не загружались и не изменялись при разработке.
Все пользовательские записи в автоматических тестах — изолированные синтетические данные.

## Хранение и миграция

Текущий ключ: `hp_direct_democracy_v6_safe`.
Формат: `{ "schemaVersion": 6, "state": <исходное состояние приложения> }`.

Источники прежних версий:

- `hp_direct_democracy_v5_full_name`
- `hp_direct_democracy_v4_pristine`
- `hp_direct_democracy_v3_clean_start`
- `hp_direct_democracy_v2_clean`
- `hp_direct_democracy_v1`
- `homoprovincialis_direct_democracy_v1`

Маркер `hp_direct_democracy_v5_full_name_initialized` больше не управляет
инициализацией и не изменяется. Старые ключи не удаляются и не перезаписываются.
В коде хранилища нет `removeItem` или `clear`.

При открытии:

1. Если есть текущий ключ, проверяется его версия и содержимое. Ошибка не приводит
   к переходу на старую базу или к созданию новой сохранённой базы.
2. Если текущего ключа нет, проверяются все найденные исторические источники.
   Автоматическая миграция допускается только для структуры, которую умеет
   обрабатывать нынешнее приложение: сообщества, участники, дела, голоса и книга
   решений с корректными типами и ссылками между записями.
3. Если исторических источников несколько, их состояния должны совпадать
   (порядок ключей объектов несущественен). Различающиеся базы не объединяются и
   не выбираются по предположению о том, какая из них новее.
4. Перед миграцией записывается и считывается обратно резервный снимок исходных
   строк localStorage. Только после успешной проверки снимка создаётся ключ v6.
5. Снимки имеют отдельные ключи `hp_direct_democracy_recovery_v1:<уникальная часть>`.
   Исторические строки остаются побайтово неизменными. Дополнительные поля JSON
   также сохраняются; записи не отбрасываются и не переименовываются.
6. Если вообще нет данных, прежнее начальное состояние с одним Создателем
   доступно в памяти. База не записывается до явного действия пользователя.
   Демонстрационные участники, предложения и голосования не добавляются.

Предыдущих исходников форматов v1–v4 в репозитории нет. Имя ключа само по себе не
подтверждает совместимость. Неизвестные структуры сохраняются без изменений и
требуют отдельного разбора, а не догадок о преобразовании полей.

## Запись, импорт и сброс

- Все записи этой версии выполняются под Web Lock одного имени на origin.
- Перед записью проверяется, что текущий ключ всё ещё совпадает с загруженной
  версией. При первой записи также проверяются исторические источники.
- Изменение в другой вкладке блокирует последующие записи устаревшей вкладки.
- При ошибке проверки или записи интерфейс возвращается к последнему успешно
  сохранённому состоянию и переходит в режим только чтения. Успешное завершение
  операции при ошибке не объявляется.
- Импорт сначала полностью проверяется, затем требует подтверждения. До замены
  создаётся проверенный снимок предыдущей базы. Предельный размер файла — 10 МиБ.
- Существующая команда сброса сохранена, но теперь сначала архивирует базу.
  Сброс требует явного подтверждения; исторические ключи и снимки не удаляются.
- При обычной работе кнопка экспорта сохраняет прежний формат состояния JSON.

Правила подсчёта голосов, пороги, десять уровней иерархии и статус Создателя не
менялись. Если сохранённые записи не соответствуют известной структуре или
содержат неизвестную роль/другого Создателя, они не исправляются автоматически:
приложение останавливает запись и сохраняет исходные данные для разбора.

## Восстановление

При ошибке в существующем блоке уведомления объясняется причина на выбранном
языке. Дизайн и состав элементов интерфейса не изменены. Изменяющие данные
кнопки отключаются, а существующая кнопка «Экспорт JSON» остаётся доступной.

В защитном режиме экспортируется пакет `hp-democracy-recovery`:

- `entries` — исходные захваченные строки, последнее известное состояние v6
  и доступные резервные снимки;
- `latestEntries` — строки, которые удалось дополнительно прочитать при экспорте;
- `restoreKey` — однозначно определённый источник, если он существует.

Если другая вкладка успела изменить данные, в пакете могут присутствовать и
исходная, и последняя доступная версии. Они не объединяются автоматически.

При ошибке миграции исходные старые ключи остаются на месте. После устранения
проблемы доступа/квоты и закрытия старых вкладок можно перезагрузить страницу:
миграция повторится из сохранённых исходников.

Чтобы восстановить проверенный снимок до импорта или сброса:

1. Сохраните текущую базу или полный пакет восстановления отдельным файлом.
2. В инструментах разработчика браузера откройте Local Storage именно этого
   origin и **скопируйте**, не удаляя и не редактируя, значение нужного ключа
   `hp_direct_democracy_recovery_v1:...` в JSON-файл. Снимки также включаются в
   пакет экспорта защитного режима: значение нужной записи является JSON-строкой
   снимка, которую следует записать в файл без внешнего строкового экранирования.
3. В работоспособном приложении используйте прежнюю кнопку импорта и выберите
   файл снимка. Поддерживаемый снимок с однозначным `restoreKey` проверяется и
   восстанавливается после подтверждения; предыдущая текущая база тоже архивируется.

При неоднозначной истории, повреждении JSON или неизвестной схеме сначала
экспортируйте пакет. Нужен отдельный анализ выбранной копии; автоматический
импорт такого пакета отклоняется. Не удаляйте ключ v6 и не очищайте браузер для
«исправления» ошибки: это может уничтожить единственную доступную копию.

## Ограничения гарантий

- localStorage не заменяет внешнюю резервную копию. Очистка профиля, сбой диска,
  удаление браузерных данных и изменения сторонним кодом находятся вне контроля
  этой страницы. Периодически экспортируйте данные на другой носитель.
- Для безопасных записей нужны Web Locks и защищённый контекст (обычно HTTPS).
  Без них работает защитный режим экспорта и чтения.
- Старые версии приложения не участвуют в блокировках. Проверки обнаруживают
  наблюдаемые изменения, но localStorage не предоставляет атомарного сравнения
  и записи против произвольного стороннего кода. Закройте старые вкладки перед
  миграцией. Для строгой общей многопользовательской транзакционности нужна
  серверная база; этот PR её не добавляет.
- При нехватке квоты для резервного снимка миграция/замена останавливается.
  Снимки не удаляются автоматически; освобождение места требует отдельного решения
  после внешнего резервирования.
- При полном запрете чтения хранилища страница не может извлечь его содержимое.
  Она ничего не заменяет, но полноту экспортируемого пакета в этом случае
  гарантировать невозможно. Восстановите доступ к исходному профилю/origin.
- Неоднозначные базы и неизвестные исторические форматы намеренно не мигрируются.
  Автоматическое объединение могло бы изменить состав участников или смысл голосов.

## Проверки

```sh
node --test tests/world-direct-democracy-data-safety.test.cjs
```

Нужны Node.js, Playwright и Chromium (`/usr/bin/chromium` по умолчанию;
`CHROMIUM_EXECUTABLE_PATH` переопределяет путь). Тесты обслуживают локальные файлы
через перехват запросов к изолированному HTTPS-origin и не обращаются к рабочему
сайту. Проверка неизменности бизнес-правил сравнивает исходники с базовым коммитом
`1ee2d76` (main на момент начала задания); для этого необходим Git и его история.

Итоговый прогон в Chromium: **102 теста пройдены, 0 ошибок, 0 пропусков**.
Проверены оба языка, все шесть исторических ключей, отсутствие/наличие маркера,
повреждённые и неоднозначные данные, ошибки резервирования/записи, откат состояния
в памяти, импорт, восстановление после сброса, сохранение истории решений и
конкурирующие вкладки. Четыре сравнения снимков RU/EN при ширине 1280/390 px
показали попиксельное совпадение с main. Исходники формул голосования, завершения
дела, иерархии, начального состояния и словаря принципов совпадают с базовой main.
