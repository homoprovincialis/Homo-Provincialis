# Мобильное отображение Homo Provincialis

База: `main`, коммит `51cc222d32595ffc171010b070744969a8f42f55` (включает PR № 1–3).
Ветка: `fix/mobile-responsive-layout`. Слияние с `main` не выполняется.

## Обследование

Все 20 HTML-страниц проверяются на ширинах 320, 375, 390, 768 и 1440 CSS-пикселей в обоих языках: 200 сочетаний. Высота окна — 900 пикселей. Проверяются закрытые и раскрытые разделы, геометрия видимых элементов и обрезание содержимого. Широкая семиколоночная таблица календаря проверяется отдельно: её существующая внутренняя прокрутка допускается, прокрутка всей страницы — нет.

В исходной матрице обнаружены проблемы в 124 из 200 сочетаний на 16 страницах. Дополнительные сценарии с заполненными карточками выявили переполнение также в переводческой среде:

- На 15 страницах общий `.site` использовал `content-box`: его рамка и отступы добавлялись сверх максимальной ширины. На телефонах документ становился шире окна на 8 пикселей; при ширине 768 — на 14 пикселей.
- В библиотеке языковые кнопки выходили за пределы шапки и обрезались при 320 пикселях на обоих языках, а также при 375/390 на русском. Общая проверка `scrollWidth` этого не обнаруживала, поскольку шапка скрывала переполнение. Проверка границ самих кнопок обнаруживает дефект.
- В заполненных карточках библиотеки длинные неразрывные имена авторов и оригинальные названия обрезались.
- Дополнительные проверки длинных пользовательских записей выявили переполнение блока проекта и карточек каталога переводческой среды: при ширине 320 документ расширялся до 1077 пикселей, при 768 — до 1118.
- В системе демократии длинное имя участника расширяло минимальную ширину колонки сетки: на тестовых данных страница при 320 пикселях расширялась до 1545–1605, а при 768 — до 1692–1776 пикселей.

На исходных страницах при 1440 пикселях выхода за пределы окна не найдено.

## Исправления

- В общем CSS при ширине до 820 пикселей рамка и отступы включены в доступную ширину `.site` через `border-box`. Исправление применяется и к календарю, и к системе демократии без изменения календарного HTML или JavaScript приложений.
- В библиотеке до 800 пикселей шапка и её инструменты могут переноситься на следующую строку. Подпись читального зала сохраняется; элементы не удаляются и не прячутся новым кодом.
- До 1120 пикселей длинные метаданные библиотеки переносятся, а дочерние элементы ограничены шириной карточки.
- До 1120 пикселей блок сведений о переводимом произведении и содержимое карточек каталога могут сжиматься и переносить длинные слова.
- В системе демократии до 1120 пикселей длинный текст переносится, а элементы сетки и поля могут сжиматься в пределах контейнера.
- Существующая отдельная прокрутка месячной таблицы календаря сохранена; новая глобальная маскировка переполнения не добавляется.

Все производственные изменения — CSS. Разметка вне `<style>`, встроенный JavaScript, общие `language.js` и `democracy-storage.js`, тексты, ссылки, переводы и резервная копия книг сравниваются с базовым коммитом. Изменений в них нет. Схемы данных, правила голосования, иерархия участников и статус Создателя не затрагиваются.

## Автоматическая проверка

Новый набор `tests/mobile-responsive-layout.test.cjs` использует реальный локальный HTTP-сервер и отдельные одноразовые браузерные контексты. Рабочие пользовательские профили не открываются. Все создаваемые книги, участники и предложения синтетические.

Проверяются:

1. Все 200 сочетаний страницы, ширины и языка, включая раскрытые `<details>`. На каждой загруженной странице последовательно устанавливаются пять ширин; отдельные сценарии приложений дополнительно запускаются с новой загрузкой на каждой мобильной ширине.
2. Сорок попиксельных сравнений всех 20 страниц с `main` при 1440 пикселях на обоих языках. Дата и случайность фиксируются для воспроизводимости. Вся высота страницы сравнивается последовательными снимками окна: PNG каждого участка должен иметь тот же SHA-256. Это ограничивает пиковую память растеризации, сохраняя проверку всего содержимого.
3. На каждой из четырёх меньших ширин и обоих языках: конвертация даты, переход между месяцами, выбор дня и внутренняя прокрутка таблицы; добавление и редактирование книги, поиск, экспорт/импорт и перезагрузка; редактирование и восстановление перевода; участник, предложение, голосование и резервная копия демократии; ответы и пояснение философского теста после перезагрузки.
4. Длинные записи в переводческой среде и системе демократии при 320 и 768 пикселях на обоих языках.
5. Все страницы через `file://` при 320 пикселях, переключение языка и перезагрузка.
6. Сохранность всех источников приложения за исключением CSS.

Эталонные файлы читаются из Git с лимитом 32 МиБ: инфографики календаря размером 1,7–1,9 МиБ превышают стандартный лимит `execFileSync`. Это исправление касается только тестов.

Проверки внешнего вида сосредоточены в новом наборе: вместо 16 прежних сравнений на 1280 пикселях проверяются все 20 страниц на обоих языках при требуемой ширине 1440 (40 сравнений). Языковой набор сохраняет все функциональные проверки и сравнение содержания; его эталон обновлён до принятой `main` (`51cc222`), уже включающей PR № 3. Первый параллельный прогон был прерван при исчерпании памяти среды; итоговые наборы запускаются последовательно.

Ранее существующая проверка языков теперь допускает изменения CSS в `<style>`, продолжая сравнивать разметку содержания, навигацию, переводы, встроенные JSON и словари приложений. Отдельный новый тест сравнивает весь исходный HTML после удаления только `<style>`, поэтому проверяется и сохранность встроенных скриптов. Проверка настольного дизайна усилена до всех 20 страниц при требуемой ширине 1440.

Для запуска нужны Node.js, Playwright, Google Chrome/Chromium и Git-история с базовыми коммитами прежних тестов и `51cc222`:

```sh
CHROMIUM_EXECUTABLE_PATH=/path/to/chrome node --test tests/mobile-responsive-layout.test.cjs
CHROMIUM_EXECUTABLE_PATH=/path/to/chrome node --test --test-concurrency=1 tests/unified-language.test.cjs tests/open-online-library-import.test.cjs tests/world-direct-democracy-data-safety.test.cjs
```

Без переменной используется `/usr/bin/chromium`. Переменная `MOBILE_CASE_PATTERN` позволяет выбирать отдельные новые сценарии для отладки; полный проверочный запуск выполняется без фильтра.

Использован Google Chrome 156.0.8078.47. Успешные итоговые наборы запускались последовательно; сохранённые успешные проверки безопасности не повторялись без изменения их предмета.

В итоговых успешных наборах нет ошибок, отменённых или пропущенных тестов. Счётчики Node.js включают объединяющие тесты: новый набор содержит 291 сценарий и один объединяющий тест.

Все 200 сочетаний страницы, ширины и языка прошли проверку. Совпали все 40 сравнений версии 1440 пикселей с принятой `main`. Проверены обычные и длинные записи, раскрытые разделы, формы, перезагрузка, JSON и оба языка, включая проход через все страницы по `file://` при ширине 320. Синтаксис JavaScript и `git diff --check` проверены. Сохранность исходных текстов, навигации, встроенного JavaScript и файлов данных подтверждена автоматическим сравнением с базовым коммитом.

Промежуточные прогоны выявили технические проблемы старой обвязки снимков (расход памяти, лимит чтения инфографик и дублирующие эталоны предыдущей версии). Они исправлены в тестах; итоговые результаты выше получены после этих исправлений. Приложения не менялись ради прохождения визуальных тестов.

## Ограничения

Браузерные проверки ширины не заменяют испытание на всех физических телефонах, браузерах, размерах системного шрифта и экранных клавиатурах. Здесь проверяется движок Google Chrome; особенности Safari и Firefox отдельно не подтверждены. При `file://` доступность сохранения зависит от браузера и его политики; прежние механизмы защиты хранилища не ослабляются.
